# 1. ÜRÜN TANIMI

Android Automotive üzerinde çalışan:

* araç telemetri katmanı

```text id="p1"
Everything = Event

```

# 4. MODÜL TASARIMI

---

## 4.1 VEHICLE LAYER

### Sorumluluk:

* araç verisini tek API olarak sunmak

### Kaynaklar:

* CarPropertyManager (primary)
* dumpsys car_service (fallback)

### Çıktı:

```text
VehicleState {
  speed
  rpm
  gear
  door
  climate
}
```

---

## 4.2 CONTEXT ENGINE

### Sorumluluk:

* sürüş durumunu anlamak
* risk / mod üretmek

### Modlar:

```text id="p3"
PARKED
CITY
HIGHWAY
TRAFFIC
RISK
UNKNOWN
```

### Output:

* ContextState
* Event trigger

---

## 4.3 EVENT BUS (CORE)

### Sorumluluk:

* tüm sistem iletişimi

### Tip:

* Kotlin SharedFlow (single source of truth)

### Event türleri:

```text
VehicleEvent
AIEvent
AudioEvent
UIEvent
SystemEvent
```

---

## 4.4 INTENT ENGINE

### Sorumluluk:

* voice → action mapping

### Örnek:

```text id="p4"
"müzik dur" → MEDIA_PAUSE
"eve git" → NAVIGATION
"hız" → VEHICLE_QUERY
```

---

## 4.5 POLICY ENGINE

### Sorumluluk:

* güvenlik + izin kontrolü

### Kural:

* speed > X → bazı intent bloklanabilir
* driver mode → AI limitlenir

---

## 4.6 AUDIO ENGINE

### Sorumluluk:

* tüm ses kanalları yönetimi

### Audio lanes:

```text id="p5"
MUSIC
NAVIGATION
AI_VOICE
ALERT
SYSTEM
```

### Priority:

```text
ALERT > AI > NAV > MUSIC
```

### Özellik:

* ducking
* focus control
* PCM streaming support

---

## 4.7 HERMES AI CLIENT

### Sorumluluk:

* WebSocket AI bağlantısı
* streaming response
* TTS audio receive

### Veri:

```text
text response
audio chunk (PCM)
context aware reply
```

---

## 4.8 OVERLAY SYSTEM

### Sorumluluk:

* floating UI
* quick AI feedback
* voice indicator

### Constraint:

* non-blocking window
* system overlay permission required

---

## 4.9 COMPOSE DASHBOARD

### Sorumluluk:

* sürüş UI
* debug panel
* vehicle state display

# 6. REAL-TIME BEHAVIOR MODEL

## Loop:

```text id="p7"
1. Vehicle state update (1s–2s)
2. Context inference
3. Event generation
4. Audio/UI update
5. AI call (if needed)
```

---

# 7. PERFORMANCE STRATEGY

## CPU kontrol:

* no busy loop
* coroutine + delay-based polling

## Memory:

* no full dumpsys caching forever
* bounded buffer (Flow capacity)

## Network:

* WS reconnect backoff
* offline fallback mode

---

# 8. RELIABILITY MODEL

| Layer   | Failure | Fallback    |
| ------- | ------- | ----------- |
| Car API | fail    | dumpsys     |
| dumpsys | fail    | last cache  |
| AI      | fail    | local rules |
| audio   | fail    | system TTS  |
| overlay | fail    | disable UI  |

---

# 9. SECURITY MODEL
